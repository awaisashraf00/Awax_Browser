RECOMMENDATIONS — topics to study before implementing the next stages
======================================================================

STUDY NOW — before Phase 3 (TcpConnection)
------------------------------------------
POSIX socket library functions (these ARE the TCP implementation):
  socket()         create an endpoint; returns a file descriptor (int)
  sockaddr_in      IPv4 address struct: sin_family, sin_port, sin_addr
  htons()/htonl()  byte order — ports/addresses must be network byte order
  connect()        starts the TCP three-way handshake to (ip, port)
  setsockopt()     options: SO_KEEPALIVE, connect/receive timeouts
  send()/recv()    partial sends and reads are NORMAL — always loop
  close()          release the fd; learn what TIME_WAIT is
  fcntl()          switch a socket to non-blocking mode
  poll()/kqueue()  wait for readability/writability without blocking (kqueue = macOS)
  errno/strerror() how socket calls report failure — check after EVERY call
  inet_pton()      reverse of inet_ntop: text -> binary (you may need it)

Core concepts:
  TCP three-way handshake (SYN, SYN-ACK, ACK) — what connect() actually does
  Network byte order (big-endian) vs host byte order
  File descriptors + RAII: own the fd in a class, close() in the destructor
  Blocking vs non-blocking I/O (why the GUI freezes if you block it)

DNS — deepen what getaddrinfo is hiding from you
-------------------------------------------------
  Record types: A, AAAA, CNAME (and what a CNAME chain is), MX, TXT, SRV
  TTL — how long resolvers may cache an answer
  Recursive vs iterative resolution: root -> TLD -> authoritative servers
  RFC 6724 — how the OS sorts multiple answers (why IPv6 ranked first)
  RFC 8305 "Happy Eyeballs" — racing IPv4/IPv6 connections
  What getaddrinfo does NOT cover: TTL access, DNSSEC, DNS-over-HTTPS,
  custom resolvers — the reason Chromium wrote its own async DNS resolver

HTTP/1.1 — before Phase 4
--------------------------
  Request line + header format; Host header (mandatory in 1.1)
  Status classes 1xx–5xx; redirects: 301/302/307/308 (and their differences)
  Content-Length vs Transfer-Encoding: chunked
  Connection: keep-alive vs close — why browsers reuse connections
  Content-Encoding: gzip/br and the Accept-Encoding negotiation
  Content-Type charset handling (bytes -> text decoding)

TLS — before Phase 5
---------------------
  What TLS adds on top of TCP: confidentiality, integrity, server identity
  Certificate chains and trust stores; what SNI is
  Layering: TCP connect first, TLS handshake second, HTTP third
  Library candidates to investigate: OpenSSL, LibreSSL, BoringSSL, platform TLS

Qt & C++ — needed continuously
-------------------------------
  The Qt event loop — why any blocking call freezes the whole UI
  Signals/slots across threads; queued vs direct connections
  QSocketNotifier — wiring raw file descriptors into the Qt event loop
  RAII, std::unique_ptr, const-correctness, error handling without exceptions
  Testing pure logic (parsers) without touching the network

Browser architecture — background reading for later
-----------------------------------------------------
  Chromium net stack: HostResolver, socket pools, connection reuse
  HSTS, DNS prefetching, speculative/preresolved connections
  DNS-over-HTTPS (DoH): what it is, why browsers ship it
  Origin model and the same-origin policy (matters once pages load subresources)
